Doppler-division MIMO on the AWR1843AOP

Replace the stock demo's time-division MIMO (one TX per chirp) with Doppler-division MIMO: all three TX fire on every chirp, each with its own per-chirp phase ramp. The radar does no processing: it streams the raw ADC samples to a capture card, and separating the transmitters is left to research code on the PC.

Status

Phases

  1. Done1. Baseline. Stock AOP demo rebuilt from source (0 warnings), flashed and verified on the board: same detections as TI's prebuilt image.
  2. Done2. TX side. All 3 TX on every chirp with per-chirp phase codes, set by a new ddmCfg command. Measured on a reflector: three copies within 2–4 dB of each other, empty band 31–35 dB down.
  3. Done3. On-chip processing. TI's DSP chain made DDM-aware (branch ddm-raw): DDM angles matched TDM within one angle bin on static targets. Superseded by phase 4, because the research needs raw data, not detections.
  4. Done4. Raw-data firmware. Branch raw-fw: the ARM configures the sensor and streams raw ADC samples over LVDS; the DSP is halted and the image holds no DSP program. Boots, streams and plots live on the board.
  5. In progress5. Hardware checks. Empty sub-band dark in a static scene, repeated stop/start, TDM captures, Doppler sign, and a target faster than the TDM limit.
Core idea

Four Doppler sub-bands, one left empty

Each TX advances its phase by a fixed step every chirp. A constant phase step is a frequency shift in slow time, so each TX's copy of a target lands in its own quarter of the Doppler spectrum. Using 4 bands for 3 TX leaves one band empty; the empty band shows which copy belongs to which TX, which resolves velocity ambiguity.

Choices

Design decisions

4 bands with 1 empty, instead of 3 bands.The empty band identifies which copy belongs to which TX, which resolves velocity over the full chirp rate (±20.6 m/s, versus ±6.9 m/s for TDM). With 3 bands there is no reference and fast targets are mislabeled. Signals without the phase code, such as receiver spurs, cannot be resolved this way.
Phase pattern in 4 static chirp definitions.Avoids the dynamic per-chirp phase API and any runtime chirp RAM updates; configuration stays a one-time setup before sensor start.
Raw data only, no processing on the chip.Research and foundation-model training need the full signal, not detections. The DSP chain is removed; the ARM only configures the sensor and streams ADC samples, which also removes the stock chain's timing limits on the frame. Raw capture is TI's own lvdsStreamCfg.
Lossless captures, no processing in the host tools.Captures keep the 16-bit I/Q exactly as the chip produced them, with the configuration text. The tools plot an unwindowed spectrum only: no windows, thresholds or TX separation, so every representation can be computed later from the same recordings.
Modify the stock demo in place, minimally.A copy of the TI demo lives in this project; changes stay confined to chirp setup, the DDM phase codes and the LVDS stream. No parallel framework, no dead code paths.
The configuration file is the single source of truth.Host tools read the sub-band count, TX mask, chirp timing and range window from the .cfg instead of their own defaults, so a changed chirp configuration is followed automatically. This is the basis for user-chosen chirp parameters.
Code standard.C99, TI SDK naming and file layout, MISRA-C:2012 style (fixed-width types, no dynamic allocation, checked return values), builds clean with warnings enabled. Host tools in typed, linted Python.
Watch list

Risks

  • Three TX at once on the AOP module: higher power and heat than TDM; may need reduced TX backoff or duty cycle.
  • Data link: frames with lost Ethernet packets are dropped, not repaired; the serial port has also dropped off the bus on a weak USB connection.
  • Phase-shifter accuracy: uncalibrated phase error leaks energy into the empty band; may need per-device phase calibration.
  • No debug probe: debugging relies on UART output, and each flash needs a manual reset in flashing mode.
