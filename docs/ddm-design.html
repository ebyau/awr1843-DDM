Doppler-division MIMO on the AWR1843AOP

Replace the stock demo's time-division MIMO (one TX per chirp) with Doppler-division MIMO: all three TX fire on every chirp, each with its own per-chirp phase ramp, and the DSP separates them in the Doppler spectrum.

Status

Phases

  1. Done1. Baseline. Stock AOP demo rebuilt from source (0 warnings), flashed and verified on the board: same detections as TI's prebuilt image.
  2. Done2. TX side. All 3 TX on every chirp with per-chirp phase codes, set by a new ddmCfg command. Measured on a reflector: three copies within 2–4 dB of each other, empty band 31–35 dB down.
  3. Done3. Processing. Verified on static targets: DDM angles match TDM within one angle bin and velocity reads 0. Receiver spurs carry no phase code and get a wrong velocity; a band-consistency check is built and awaits a hardware comparison.
  4. In progress4. Validation. Raw ADC capture through a DCA1000EVM, decoded on the PC independently of the firmware: TX copies, motion direction and the top view confirmed on the board. Still open: a target faster than the TDM limit (±6.9 m/s).
Core idea

Four Doppler sub-bands, one left empty

Each TX advances its phase by a fixed step every chirp. A constant phase step is a frequency shift in slow time, so each TX's copy of a target lands in its own quarter of the Doppler spectrum. Using 4 bands for 3 TX leaves one band empty; finding the empty band tells the DSP which copy belongs to which TX, which resolves velocity ambiguity.

Results

Raw data decoded on the PC

The radar streams its ADC samples to a DCA1000EVM capture card while the firmware keeps running. A Python decoder repeats the DDM steps on the PC (range and Doppler FFTs, empty-band search, 12-element virtual array), so it checks the firmware's choices without sharing its code.

Choices

Design decisions

4 bands with 1 empty, instead of 3 bands.The empty band identifies which copy belongs to which TX, which resolves velocity over the full chirp rate (±20.6 m/s, versus ±6.9 m/s for TDM). With 3 bands there is no reference and fast targets are mislabeled. Signals without the phase code, such as receiver spurs, cannot be resolved this way.
Phase pattern in 4 static chirp definitions.Avoids the dynamic per-chirp phase API and any runtime chirp RAM updates; configuration stays a one-time setup before sensor start.
Fold the detection matrix across sub-bands.The CFAR accelerator needs the whole range-Doppler detection matrix in 32 KB. A raw 256 × 128 matrix is 64 KB and stalls the DSP, so the 4 sub-bands are summed into one 256 × 32 matrix (16 KB, same as stock) before detection. This also adds the energy of the 3 TX copies.
Make the AOP datapath DDM-aware.TI's AOP chain only accepts one TX per chirp. The chirp parser and Doppler stage learn a DDM mode instead of a separate code path. Phase 2 is checked on the standard (non-AOP) chain, which accepts all-TX chirps.
Keep the chirp profile and antenna geometry.Only the multiplexing changes, so results can be compared one-to-one with the stock firmware, and the existing angle-of-arrival stage is reused.
Modify the stock demo in place, minimally.A copy of the TI demo lives in this project; changes stay confined to chirp setup, Doppler processing and TX separation. No parallel framework, no dead code paths.
Validate with raw data decoded on the PC.The firmware's own output can only confirm itself. Raw ADC samples, captured with the xwr library's DCA1000 driver and decoded in Python, give an independent check and the true band powers needed to set the spur threshold. No firmware change was needed: raw streaming is TI's lvdsStreamCfg, and the phase codes are already in the samples.
The configuration file is the single source of truth.Host tools read the sub-band count, TX mask, chirp timing and range window from the .cfg instead of their own defaults, so a changed chirp configuration is followed automatically. This is the basis for user-chosen chirp parameters.
Code standard.C99, TI SDK naming and file layout, MISRA-C:2012 style (fixed-width types, no dynamic allocation, checked return values), builds clean with warnings enabled. Host tools in typed, linted Python.
Watch list

Risks

  • Three TX at once on the AOP module: higher power and heat than TDM; may need reduced TX backoff or duty cycle.
  • Memory: the larger radar cube must still fit in L3 alongside detection buffers; fallback is 128 range bins.
  • Phase-shifter accuracy: uncalibrated phase error leaks energy into the empty band; may need per-device phase calibration.
  • No debug probe: debugging relies on UART logs and output data, and each flash needs a manual power cycle.
